# Entities

A catalog of every kind of class and file the project builds, grouped by layer: what each kind
does, where it lives, which design file explains how to write it, and one real file to copy. Its
name suffix is in [module-anatomy.md](module-anatomy.md), section "Naming", and the module kinds
are in [project-structure.md](project-structure.md), section "Module kinds"; this file repeats
neither. A responsibility matrix at the end says which kind reaches which.

Read when: about to add a class, interface, object or file of a kind not written before in the
task; deciding which kind a new piece of code is; checking what a kind may call; reviewing whether
a new class fits a kind that already exists.

"Where" reads module kind · source set · package segments after `<platform>`. "common" stands for
`commonMain`; "feature" is any feature module kind that has the entity.

## Responsibility matrix

What each kind reaches, and what it leaves to others, as the code does it today. The owner column
links the file that states each point.

| Kind | Reaches | Leaves to others | Owner |
|---|---|---|---|
| Process entry, entry object | The app graph; start-up work; the screen host or the root graph holder | Drawing anything | [platform-mirroring.md](platform-mirroring.md) "Startup" |
| Screen host | A root graph, the root host, root content, platform permission and tap delivery | Drawing anything of its own; navigation decisions | [ui-compose.md](ui-compose.md) "Screens and routes", [navigation.md](navigation.md) "Deep links" |
| Root host | The root graph's stores and feature graph creators, the root component, root-level element controllers, the permission session | Composables; mapping a screen to a section by hand (the root child does it) | [navigation.md](navigation.md) "Root stack" |
| Root content | The root dependencies bundle, routes, overlay state holders, the system message host, the theme | Holding stores; disposing anything | [navigation.md](navigation.md) "Root-level elements" |
| Screen component | Its feature graph (each store read once), its controller, its `StateKeeper` | Exposing stores to the route; they stay `internal` | [navigation.md](navigation.md) "Screen components" |
| Route | The controller's state, the UI mapper, the screen composable | Mapping logic, which the UI mapper holds | [ui-compose.md](ui-compose.md) "Screens and routes" |
| Screen composable | The UI model, `dispatch`, tokens, shared composables | Decisions about data, which stay in the store | [ui-compose.md](ui-compose.md) "Screens and routes" |
| Controller | Stores through `stateFlow`, `accept` and `bind`, store-to-store mappers, an `onLabel` callback | Disposing stores; the owner that created them does | [mvi.md](mvi.md) "Controllers" |
| Executor | A usecases wrapper, the system message provider, the coroutine context provider, a paginator | Switching dispatchers; holding application state outside `State`; calling a platform service, which a usecase fronts | [mvi.md](mvi.md) "Executors and state", [concurrency-and-lifecycle.md](concurrency-and-lifecycle.md) "Main thread" |
| Reducer | Nothing | Everything but returning a `copy` | [mvi.md](mvi.md) "Reducer" |
| Usecase | A source, a repository, or the platform API it fronts | Turning a failure into a message, which the executor does | [data-layer.md](data-layer.md) "Sources and usecases" |
| Source implementation | A service, the safe-call wrapper, response-to-domain mappers | Throwing; every failure is a `CallResult` | [data-layer.md](data-layer.md) "Sources and usecases" |
| Service implementation | The `HttpClient` and the URL constants | Retrying and catching, which the safe call around it does | [data-layer.md](data-layer.md) "Network" |
| Worker, background manager | Exported persistence usecases, its own usecases, the notification manager | Showing messages; a failure becomes a work result and a log line | [error-handling.md](error-handling.md) "Failure to message" |
| Platform service implementation | Platform APIs, external contracts, the coroutine context provider | Providing an external contract's binding; the entry module does | [dependency-injection.md](dependency-injection.md) "Module and platform components" |
| Feature module | `api` contracts through its dependencies contract, shared base modules, platform services, external contracts, core modules | Depending on another screen feature or on the entry module | [project-structure.md](project-structure.md) "Dependency edges" |
| Test | The real code and its real graph, over fakes and library mocks | A real database, network or background work | [testing.md](testing.md) "Structure" |
